WhenSelected

Selection, read
the way you mean it

WhenSelected(...) has the same behavior as Selection(...). The difference is the reading direction: it keeps the list chain intact and adds selection at the end.

Selection ListFeed
TargetIListFeed<T>
ReturnsIListFeed<T>
RoleSelection sugar

Why the extra name?

Base APIConvenience API
Favorites.Selection(SelectedFavorite)Favorites.WhenSelected(SelectedFavorite)
Queue.Selection(SelectedCards)Queue.WhenSelected(SelectedCards)

The behavior is identical. WhenSelected just reads more naturally when you want to say "this list is used with selection."

Single selection

public IState<string> SelectedCity => State<string>.Empty(this);

public IListFeed<string> Cities =>
    ListFeed
        .Value(["Seoul", "Busan", "Incheon", "Daegu", "Jeju"])
        .WhenSelected(SelectedCity);

XAML

Like Selection, the XAML only binds the list. No SelectedItem binding is needed.

<ListBox ItemsSource="{Binding Cities}" />

Multiple selection

public IState<ImmutableList<WorkCard>> SelectedCards =>
    State.Value(this, () => ImmutableList<WorkCard>.Empty);

public IListFeed<WorkCard> QueueWithSelection =>
    Queue.WhenSelected(SelectedCards);

When to use it

Use it in samples and docs where WhenSelected reads more naturally than Selection for MVVM users.

When to use Selection

Use Selection when you want the base API name, existing code consistency, or direct reference to the underlying behavior.

Caution

WhenSelected is for list feeds only. It is not a projection API for turning a single value feed into a list.
