WhenSelected

선택 의미를
체이닝으로 보완

WhenSelected(...)는 Selection(...)과 같은 선택 동기화 흐름을 표현합니다. 차이는 이름이 아니라 읽히는 방향입니다. 리스트를 만들고 그 흐름에 선택 상태를 붙인다는 의미를 체이닝으로 보완합니다.

Selection의 의미 보완

기본 API편의 API
Favorites.Selection(SelectedFavorite)Favorites.WhenSelected(SelectedFavorite)
Queue.Selection(SelectedCards)Queue.WhenSelected(SelectedCards)

동작은 선택 state와 리스트 feed를 연결하는 것으로 같습니다. 다만 WhenSelected는 리스트 정의 마지막에 붙여 “이 목록은 선택 상태와 함께 쓰인다”는 의도를 더 자연스럽게 드러냅니다.

단일 선택

public IState<string> SelectedCity => State<string>.Empty(this);

public IListFeed<string> Cities =>
    ListFeed
        .Value(["Seoul", "Busan", "Incheon", "Daegu", "Jeju"])
        .WhenSelected(SelectedCity);

XAML

Selection과 동일하게 XAML은 리스트만 바인딩합니다. SelectedItem 바인딩은 쓰지 않습니다.

<ListBox ItemsSource="{Binding Cities}" />

다중 선택

public IState<ImmutableList<WorkCard>> SelectedCards =>
    State.Value(this, () => ImmutableList<WorkCard>.Empty);

public IListFeed<WorkCard> QueueWithSelection =>
    Queue.WhenSelected(SelectedCards);

언제 쓰나요?

MVVM 사용자에게 Selection보다 WhenSelected가 더 자연스럽게 읽히는 예제나 샘플에서 씁니다.

언제 Selection을 쓰나요?

문서의 기본 설명, API 원형, 기존 코드와의 일관성을 우선할 때는 Selection을 씁니다.

주의점

WhenSelected는 리스트 feed 전용입니다. 단일 값 feed를 리스트처럼 바꾸는 projection API가 아닙니다.
