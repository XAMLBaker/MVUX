容易混淆的点

Luke.Mvux 在熟悉的 MVVM 之上增加了 feed/state 模型。刚开始看会觉得名字很多， 但判断标准很简单：它是只读，还是可写。

范围WPF, Avalonia
目的教学与演示
核心Feed / State / View

这是 Uno MVUX 吗？

不是。这是一个面向 WPF 与 Avalonia 的独立重实现，目标是复现 Uno Platform MVUX 的 API 形态和使用体验。并不是复制 Uno 源码的项目。

支持哪些平台？

按当前文档和示例，支持目标是 WPF 和 Avalonia。WinUI 3 与 MAUI 不在当前范围内。

可以直接用于生产吗？

项目主要目标是教学和演示。用于真实应用时，需要你自行评估 API 稳定性、错误处理以及平台边界场景。

Feed 和 State 的区别

IFeed<T> 是只读数据流。IState<T> 是既可读取当前值、也可写入当前值的 feed。

ListFeed 和 ListState 的区别

ListFeed 用于展示列表，ListState 用于可编辑列表。像收藏夹这种需要增删的场景，应使用 ListState。

为什么没有 ListState.Async？

异步查询列表由 ListFeed.Async 负责。如果用户需要编辑初始列表，建议先查询，再用 ListState.Value 管理。

Selection 与 WhenSelected

Selection 是基础 API，WhenSelected 是为了 MVVM 阅读体验提供的便捷 API。两者都会连接列表 feed 与选择 state。

还要绑定 SelectedItem 吗？

推荐不绑定。应在模型中用 Favorites.Selection(SelectedFavorite) 连接，XAML 只绑定 ItemsSource。

为什么需要 UseMvux？

选择同步需要与平台控件连接。应用启动时调用一次 UseMvux()，才能注册 WPF/Avalonia 的 selection sync。

为什么使用 owner 模式？

像 State.Value(this, () => value) 这样传入 owner 后，即使多次访问同一模型属性，也会复用同一个 state 实例。

命令名如何映射？

按方法名原样暴露。比如 AddFavorite 方法，绑定方式就是 Command="{Binding AddFavorite}"。

推荐阅读顺序

如果是第一次接触，建议按以下顺序阅读：State、ListFeed、ListState、Selection、WhenSelected、FeedView、Commands。
