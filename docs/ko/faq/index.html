헷갈리는 지점

Luke.Mvux는 익숙한 MVVM 위에 feed/state 모델을 얹습니다. 처음에는 이름이 많아 보이지만, 기준은 읽기 전용인지 쓰기 가능한지입니다.

문서 홈Selection 보기
범위WPF, Avalonia
목적교육과 데모
핵심Feed / State / View

Uno MVUX인가요?

아니요. Uno Platform MVUX의 API 모양과 사용 감각을 WPF와 Avalonia에서 독립적으로 재구현한 라이브러리입니다. Uno 소스를 복사한 프로젝트가 아닙니다.

지원 플랫폼은?

현재 문서와 샘플 기준 지원 대상은 WPF와 Avalonia입니다. WinUI 3와 MAUI는 현재 범위에 넣지 않습니다.

프로덕션용인가요?

목적은 교육과 데모입니다. 실제 앱에 쓰려면 API 안정성, 오류 처리, 플랫폼별 edge case를 직접 검토해야 합니다.

Feed와 State 차이

IFeed<T>는 읽기 전용 데이터 흐름입니다. IState<T>는 현재 값을 읽고 쓸 수 있는 feed입니다.

ListFeed와 ListState 차이

ListFeed는 보여주는 목록, ListState는 수정하는 목록에 씁니다. 즐겨찾기처럼 추가/삭제가 필요하면 ListState가 맞습니다.

ListState.Async는 없나요?

비동기 조회 목록은 ListFeed.Async가 담당합니다. 사용자가 편집할 초기 목록이 필요하면 조회 후 ListState.Value로 관리하는 흐름을 선택하세요.

Selection과 WhenSelected

Selection은 기본 API이고, WhenSelected는 MVVM 사용자에게 더 자연스럽게 보이도록 추가된 편의 API입니다. 둘 다 리스트 feed와 선택 state를 연결합니다.

SelectedItem 바인딩은?

사용하지 않는 방향을 권장합니다. Favorites.Selection(SelectedFavorite)처럼 모델에서 연결하고, XAML은 ItemsSource만 바인딩합니다.

UseMvux가 필요한 이유

선택 동기화는 플랫폼 컨트롤과 연결되어야 합니다. 앱 시작 시 UseMvux()를 호출해야 WPF/Avalonia selection sync가 등록됩니다.

왜 owner 패턴을 쓰나요?

State.Value(this, () => value)처럼 owner를 넘기면 같은 모델 프로퍼티에 여러 번 접근해도 같은 state 인스턴스를 재사용합니다.

커맨드 이름은?

메서드 이름 그대로 노출됩니다. AddFavorite 메서드는 Command="{Binding AddFavorite}"로 바인딩합니다.
